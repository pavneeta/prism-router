01 · How it works

Four stages. One request path.

Prism Router owns which model runs. LiteLLM owns how it is called. Classification and selection target negligible overhead on the heuristic path.

  1. 1.0

    Classify the turn.

    Heuristic classifier maps the messages to a task type — code generation, review, tool-use agent, reasoning, summarization, chat — with confidence. Optional LLM classify only when needed.

    Target p99 < 20–50 ms · heuristic path

  2. 2.0

    Apply the intelligence floor.

    Benchmark seed scores set per-task accuracy thresholds. Models that cannot clear the floor for that task type are ineligible — cheaper never means under-provisioned.

    DeepSWE · SWE-bench · Terminal-Bench · AA · Arena

  3. 3.0

    Minimize effective cost.

    Among eligible models, pick the lowest effective $/request — counting cached vs cold token rates, not list price alone. North star: lower $/task completion without giving up accuracy or turn latency.

    model-router/auto · OpenAI-compatible API

  4. 4.0

    Stick the session.

    Session affinity via X-Session-Id keeps multi-turn work on one model so provider prompt caches stay warm. Flipping mid-session destroys cache hits; the policy prices that tradeoff explicitly.

    Local exact cache · provider cache hints

03 · Cache-aware

Stickiness beats naive re-routing.

Cost includes cached-token rates and session cache state. The router prefers affinity when it wins on effective dollars.

  • Local exact cache

    Identical prompts return immediately without a provider hop.

  • Session affinity

    Pass X-Session-Id so follow-up turns stay on the sticky model.

  • Provider cache hints

    When supported, the gateway enables provider prompt-cache flags via LiteLLM.

05 · Quick start

Running in minutes.

Clone, install, add provider keys, start the gateway. Dry-run mode routes without provider spend.

Clone the repo → Full usage guide
  1. 01

    git clone https://github.com/pavneeta/prism-router.git

  2. 02

    python3 -m venv .venv && source .venv/bin/activate

  3. 03

    pip install -e ".[dev]" && cp .env.example .env

  4. 04

    Add provider keys, then model-router → http://127.0.0.1:4000

  5. 05

    Or dry-run: MODEL_ROUTER_DRY_RUN=true model-router
